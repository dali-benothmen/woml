# WOML 1.0.4

WOML 1.0.4 introduces an explicit two-README model so the npm package
and the GitHub repository can evolve independently without surprise
drift, plus a verifier that fails any future release which would
publish a stale or divergent README.

## Architecture

There are now two README files, each with a deliberate role:

- **`README.md`** at the repository root is the GitHub-facing README.
  It is rendered on `github.com/dali-benothmen/woml` and is the
  primary user-facing document for contributors and visitors. It is
  the canonical source of truth.
- **`woml-cli/README.md`** inside the CLI package is the npm-facing
  README. It is what `npmjs.com/package/woml-cli` displays and what
  every `npm install woml-cli` user sees in their terminal via
  `npm home woml-cli` or `npm view woml-cli readme`. It is the file
  bundled into the published tarball.

For this release both files are byte-identical (the npm-facing README
is a copy of the canonical GitHub README), but they are intentionally
free to diverge in future releases — for example, the npm-facing
README could omit the contribution and development sections that only
matter to GitHub visitors, or include an npm-specific install banner
that would be redundant on GitHub.

## Drift prevention

The release bundler in `woml-cli/scripts/native-release.ts` (line
227) reads the README from `woml-cli/README.md` and copies it into
the staged package output, just as it always has. The new step is
the verifier inside `woml-cli/scripts/release-package.ts`:

- `verifyPackagedReadmeMatchesSource(output)` runs inside
  `prepareAndVerify()` immediately after `prepareMainPackage` and
  before `inspectNpmPack`.
- It compares `output/README.md` (the staged, packaged README) with
  `repositoryRoot/README.md` (the canonical GitHub README) by full
  string equality.
- If they differ, it throws an error explaining that the two README
  files have drifted and the release bundler would publish a stale
  document.

This check makes the drift bug that previously slipped through
impossible to ship again. The first `bun run build:release` after any
divergence will fail loudly at the staging step, before any tarball
is produced.

## Operational notes

- Both files currently contain the same 432-line content. Future
  releases that intentionally want them to differ should keep both
  files updated and either (a) accept the drift by removing or
  adjusting the verifier, or (b) make the npm-facing README a strict
  subset of the canonical one and document that contract.
- `woml-cli/README.md` is included in the explicit `files` allowlist
  in `woml-cli/package.json` and listed in
  `woml-cli/scripts/release-contract.ts` (`publicPackageFiles`).
- `woml-cli/tests/release-identity.test.ts` asserts that both README
  files reference the canonical `woml-cli` install command so neither
  can drift to a stale package name without the test failing.
