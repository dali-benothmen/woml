# WOML 1.0.4

WOML 1.0.4 is a packaging-bug fix release. Every `woml-cli` tarball
published since v1.0.2 (the rename release) shipped the wrong README —
the 124-line hello-world example left behind in `woml-cli/README.md`
after the rename to `woml-cli` in `b3a0f80` — instead of the canonical
432-line Smart Organizer README at the repository root. This release
fixes the bundler so the packaged README matches the canonical source
on every future release.

## Highlights

- **Published README now matches the canonical root README.** Every
  `woml-cli@1.0.4` tarball on npmjs.com ships the full 432-line README
  (tagline, install section, real-world examples, WOML vs alternatives
  comparison, common commands, support/security, contributing, license).
  The pre-1.0.4 tarballs (1.0.2, 1.0.3) shipped a stale 124-line
  hello-world README.
- **Dead README removed.** `woml-cli/README.md` (the leftover 124-line
  file) is deleted. There is now a single source of truth for the
  public README: `README.md` at the repository root.
- **Drift caught earlier next time.** The verifier now reads the same
  file the bundler writes from (the repository root) and the bundler
  fails loudly if the two diverge. A new check inside
  `release-package.ts prepareAndVerify` compares the staged
  `release/main/README.md` against `repositoryRoot/README.md` byte-for-
  byte and throws on mismatch.
- Package identity frozen at `woml-cli@1.0.4` (public) and the matching
  `@woml-org/cli-*@1.0.4` native engines for darwin-x64, darwin-arm64,
  win32-x64-msvc, win32-arm64-msvc, linux-x64-gnu, and linux-arm64-gnu.
- All six manifests pinned at `1.0.4`; the private compiler
  (`@woml/compiler`), VS Code extension (`woml-language`), and root
  monorepo (`woml-repository`) packages follow the same version.

## Bug details

The release bundler in `woml-cli/scripts/native-release.ts` line 227
copied the README from `woml-cli/README.md` (the old 124-line hello-
world file that was kept around as a stub after the rename) instead of
the canonical `README.md` at the repository root. Every `npm publish`
of `woml-cli@1.0.2`, `woml-cli@1.0.3` (had it published), and any
in-progress CI builds all shipped the wrong content.

The verifier check in `woml-cli/scripts/verify-documentation.ts` line
119 reads from the correct path (`repositoryRoot/README.md`) but never
compared it to the bundled output, so the drift went undetected by
CI.

Fix:

- `woml-cli/scripts/native-release.ts`: `cliRoot/README.md` →
  `repositoryRoot/README.md` (the bundler now reads from the canonical
  file the verifier checks).
- `woml-cli/scripts/release-package.ts`: new
  `verifyPackagedReadmeMatchesSource` step inside `prepareAndVerify`,
  comparing `output/README.md` against `repositoryRoot/README.md` by
  SHA-256. Throws if they differ.
- `woml-cli/README.md`: deleted (dead code; verifier and bundler both
  agree on the canonical path now).
- `woml-cli/tests/release-identity.test.ts`: dropped
  `woml-cli/README.md` from the installation-metadata loop since the
  file no longer exists.

## Release infrastructure

- `core/woml-native/tests/separation.rs` assertion updated to require
  `woml-engine = "1.0.4"`.
- `Cargo.lock` regenerated.
- `examples/production/deployment/Dockerfile` bumped to install
  `woml-cli@1.0.4` by default.

## Installation

```bash
bun add --global woml-cli
```

```bash
npm install --global woml-cli
```

## Upgrading

`bun update -g woml-cli` or `npm update -g woml-cli` will move a 1.0.x
installation to 1.0.4. No workflow, API, or CLI behavior changes —
this release only fixes which README is shipped inside the package.
