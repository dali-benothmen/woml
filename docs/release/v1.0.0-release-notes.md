# WOML 1.0.0

WOML 1.0.0 is the first production release of markup-first workflow
automation: workflows are readable `.woml` documents, while a durable Rust
engine owns execution, history, recovery, and control.

## Highlights

- Run one file, many files, or a directory with `woml run`.
- Keep automations active for manual, webhook, schedule, interval, event,
  Slack, Telegram, Discord, and WhatsApp triggers.
- Build durable DAGs with sequential steps, parallel work, `choose`, `switch`,
  forked branches and selected joins.
- Pause for human approval and resume from provider buttons or capability
  URLs.
- Use retries, idempotency, workflow calls, lifecycle hooks, cancellation,
  runtime policies, durable state, backup, retention, and recovery.
- Use supervised HTTP, SQL database, storage, cache, event, state, and workflow
  services from authored JavaScript.
- Reuse local JavaScript/TypeScript modules, custom steps, and custom
  notification providers.
- Operate foreground or background runtimes with structured, colored output,
  run inspection, log following, provider diagnostics, and actionable errors.
- Author `.woml` files with the WOML VS Code language extension.

## Installation

After the npm release is public, install the single global package:

```bash
bun add --global woml
```

or:

```bash
npm install --global woml
```

Bun 1.3.14 or newer is required even when npm performs the installation. The
main package automatically selects the matching native engine package for the
supported Windows, macOS, or Linux platform.

## Security and production boundaries

- WOML source and imported modules are trusted application code, not hostile
  multi-tenant code.
- Runtime state can contain workflow data and is not encrypted by WOML. Use
  owner-only permissions, encrypted disks, and encrypted backups where needed.
- Secrets belong in `woml secrets`, environment-backed production secrets, or
  permission-checked mounted files—not source or durable state.
- Public triggers should use authentication and TLS through a reviewed reverse
  proxy. The administration endpoint remains loopback-only.
- Run untrusted workloads inside a dedicated OS account or constrained
  container with an explicit outbound-network policy.

Read [SECURITY.md](../../SECURITY.md), the
[data-security guide](../woml-data-security.md), and the
[production deployment guide](../woml-production-deployment.md) before a
public deployment.

## Known v1 boundaries

- The TypeScript/Bun frontend is the only WOML parser and compiler in v1; Rust
  execution starts from the versioned compiled model.
- Local imported modules are supported. A public package registry, signed
  third-party packages, and the expanded provider-extension architecture are
  not part of v1.0.0.
- The built-in local SQLite authority is the v1 durable store. External state,
  cache, object-storage, and queue adapters remain future work.
- WOML provides a professional terminal inspector, not a hosted web control
  plane.
- The package does not silently migrate in-flight runs from the retired
  JavaScript-chaining SDK.

## Release integrity

The public package contains no embedded `.node` binary. Eight exact-version
native packages are built and load-tested on their matching platforms. The
release workflow seals every package with SHA-256 metadata, collects the full
family, and allows npm publication only from the approved `v1.0.0` tag through
the protected publishing environment.
