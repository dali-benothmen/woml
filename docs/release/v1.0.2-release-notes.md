# WOML 1.0.2

WOML 1.0.2 is a documentation and cleanup release that ships the rewritten
README to npm and removes the obsolete name-dispute letter. The release
artifacts are otherwise identical to 1.0.1.

## Highlights

- New README on npm: a single-tagline intro, a "Why another automation
  tool?" section, four real-world example workflows, a side-by-side
  comparison table, and an annotated list of common commands.
- Package identity frozen at `woml-cli@1.0.2` (public) and the matching
  `@woml-org/cli-*@1.0.2` native engines for darwin-x64, darwin-arm64,
  win32-x64-msvc, win32-arm64-msvc, linux-x64-gnu, and linux-arm64-gnu.
- All six manifests pinned at `1.0.2`; the private compiler (`@woml/compiler`),
  VS Code extension (`woml-language`), and root monorepo (`woml-repository`)
  packages follow the same version.

## Cleanup

- Removed `docs/release/npm-name-dispute.md`. The dispute is moot: the
  unscoped `woml` name was released by manual unpublish, and the project
  ships as `woml-cli`.
- Removed `hello.woml`. The rewritten README uses a single-step quick-start
  example that is easier to read inline.
- Updated `examples/production/deployment/Dockerfile` to install
  `woml-cli@1.0.2` by default.

## Release infrastructure

- Dropped musl native targets (linux-x64-musl, linux-arm64-musl). Six
  glibc-based targets remain and are the only ones built, sealed, and
  published.
- Removed the `container-smoke` job from the release workflow. Per-platform
  smoke tests already exercise the same paths inside a non-root CLI run.
- Pinned the shard runner per-test timeout at 60 seconds (was 30). This
  covers the native atomic-activation gate on shared CI runners where
  loading the Rust addon + spinning up the HTTP server is slow.
- Ignored `RUSTSEC-2026-0258` (h2 0.3.27) in `cargo audit`. `actix-http`
  3.13.3 pins `h2 ^0.3`; the fix requires `h2 >= 0.4.16` and the upstream
  `actix-web` migration is still pending.

## Installation

```bash
bun add --global woml-cli
```

Bun 1.3.14 or newer is required even when npm performs the installation.
The main package automatically selects the matching native engine package
for the supported platform.

## Upgrading

`woml-cli@1.0.2` is a drop-in replacement for `1.0.1`. No code changes,
no schema changes, no native ABI changes — only README, docs, and CI
artifacts.
